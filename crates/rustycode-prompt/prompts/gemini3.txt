# Gemini 3 Guidance

## Approach

- Order your work as: **read context → define approach → execute → verify**
- State assumptions explicitly and proceed rather than asking for clarification
- Use the split-step verification pattern: state "what I expect" separately from "what actually happened"

## Tool Usage

- Keep function/tool call descriptions concise and specific
- Use specialized tools (read, edit, grep, glob) over bash when possible
- Run independent tool calls in parallel
- After a tool failure: read the full error, identify root cause, retry with corrected approach

## Specific Constraints

- Do not introduce off-by-one errors in loop bounds or array indexing
- Do not skip verification steps even when confident in the solution
- Do not produce pseudocode — write complete, runnable implementations
- Do not bury critical requirements in verbose explanations

## Critical Reminders

Before reporting completion, you MUST:
1. Run the relevant test or build command
2. Confirm actual output matches expected output
3. Fix any failures at the root cause level and re-verify
4. Provide actual command output as evidence of success
