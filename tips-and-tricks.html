Writing Effective Prompts

Be Specific About Files

# Vague
"Fix the bug"

# Better
"Fix the null pointer dereference in src/auth/session.rs line 47
where user.profile can be None after account deletion"

Specify the Outcome

# Vague
"Make it better"

# Better
"Add input validation to the register endpoint:
- email must be valid format
- password must be 8+ chars with uppercase and number
- return 400 with specific error messages for each failure"

Provide Context

# Let RustyCode know about constraints
"This project uses PostgreSQL 15 and we can't add new dependencies.
The solution should use only the existing 'tokio-postgres' crate."

Workflow Patterns

Incremental Development

Break large features into small, verifiable steps:

Step 1: "Create the User struct with fields: id, email, created_at"
Step 2: "Add a UserRepository with CRUD methods using our existing PostgresPool"
Step 3: "Add unit tests for UserRepository covering create, find, and delete"
Step 4: "Wire the repository into the user routes"

Test-First Workflow

# Ask RustyCode to write the test first
"Write a test for a function that validates email addresses.
It should accept user@example.com and reject 'invalid' and '@nouser.com'.
Don't implement the function yet."

# Then implement
"Now implement the validate_email function to make those tests pass."

Code Review

"Review the changes in src/api/handlers.rs since the last commit.
Focus on: error handling, SQL injection risks, and missing input validation.
Don't make changes — just list the issues."

Autonomous Mode for Large Tasks

# Let RustyCode plan and execute a multi-step task
rustycode run "Implement a complete user registration flow:
1. Create User model and migration
2. Add POST /api/register endpoint with validation
3. Add email verification token generation
4. Write integration tests
5. Verify everything compiles and tests pass"

Setting Up Project Context

CLAUDE.md / Project Instructions

Create a CLAUDE.md file in your project root with project-specific instructions:

# CLAUDE.md

## Project
This is a Rust web API using Axum with a PostgreSQL database.

## Conventions
- Use `anyhow` for errors in handlers, `thiserror` for library crates
- All routes go in `src/routes/`
- Tests use `#[tokio::test]` with a test database
- Never use `unwrap()` in production code

## Architecture
- `src/routes/` - HTTP handlers
- `src/models/` - Database models
- `src/services/` - Business logic
- `src/repo/` - Data access layer
RustyCode automatically reads CLAUDE.md when it opens your project, so it understands your conventions from the start.

Using Multiple Providers

Switch Providers Per Task

# Use Claude for complex reasoning
rustycode run --provider anthropic --model claude-opus-4-7 \
  "Design the database schema for a multi-tenant SaaS app"

# Use a cheaper model for simple edits
rustycode run --provider anthropic --model claude-haiku-4-5 \
  "Fix the typo in the README"

# Use a local model for offline work
rustycode run --provider ollama "Format this file"

Model Selection Guide

TaskRecommended ModelWhy
Quick fixes, simple editsHaiku / gpt-4o-miniFast, cheap, good enough
Feature developmentSonnet / gpt-4oBest balance of speed and quality
Architecture, debuggingOpus / o3Deepest reasoning
Offline / sensitive codeOllama (local)No data leaves your machine

Debugging with RustyCode

Paste Error Messages

"I'm getting this error when running `cargo build`:

error[E0599]: no method named `parse` found for struct `String`
  --> src/parser.rs:42:18

Help me fix it."

Ask for Investigation First

"Users are reporting 500 errors on the /api/orders endpoint.
Look at the handler code and database queries to find the root cause.
Don't fix it yet — just tell me what's wrong."

Use LSP Tools for Navigation

"Use lsp_references to find all callers of process_payment,
then show me the call hierarchy with lsp_incoming_calls."

Refactoring Large Codebases

Scope the Refactor

"Extract the authentication logic from src/routes/users.rs into
a new module src/middleware/auth.rs. Keep the same API surface.
Don't touch any other files."

Use LSP Tools

RustyCode has built-in LSP integration. Ask it to:

  • Find all references to a symbol before renaming
  • Check call hierarchies to understand blast radius
  • List document symbols to understand file structure
"Find all callers of the `process_payment` function across
the codebase, then rename it to `handle_payment_transaction`.
Update every call site."

Performance Tips

Reduce Context Noise

# Instead of reading the whole project
"Focus only on src/auth/ and src/middleware/. Ignore everything else."

# Be explicit about what to skip
"Don't read test files or generated code. Only look at src/lib/ and src/services/."

Use Headless Mode for Automation

# Run as part of a CI pipeline
rustycode run --timeout 120 "Review the staged changes and suggest improvements"

# Batch processing
for file in src/*.rs; do
  rustycode run --timeout 60 "Add documentation comments to $file"
done

Using MCP, ACP & A2A

MCP for External Tools

Connect databases, APIs, and services via MCP servers:

# In .rustycode/config.toml
[[mcp_server]]
name = "postgres"
transport = "stdio"
command = "npx"
args = ["-y", "@modelcontextprotocol/server-postgres", "postgresql://localhost/mydb"]

Once configured, RustyCode can query your database directly. See Skills & MCP for full setup.

ACP for IDE Integration

# Start the ACP server for IDE connection
rustycode serve

A2A for Multi-Agent Coordination

# Enable A2A in config
[a2a]
enabled = true
port = 8080

Common Issues & Solutions

"Edit not found" errors

If RustyCode can't find the exact text to edit, it automatically tries three matching strategies: exact match, line-ending-normalized match, and trimmed match. If it still fails:

"Read src/main.rs lines 30-50 first, then apply the edit to the
function starting with 'fn handle_request'."

Timeout in autonomous mode

Increase the wall-clock timeout:

rustycode run --timeout 600 "Implement the full API"

Wrong file edited

Use git to undo and be more specific:

git checkout -- src/wrong_file.rs

# Then be explicit
"Edit ONLY src/services/user_service.rs. Do NOT modify any other files."

API rate limiting

If you hit rate limits during long autonomous sessions:

  • Use MIN_TOOL_CALLS_TO_STOP = 5 (default) to avoid excessive API calls
  • Reduce MAX_TOOL_TURNS to 15
  • Switch to a provider with higher rate limits

MCP server not connecting

  • Ensure Node.js is installed (node --version)
  • Check the command and args in your config
  • Try running the MCP server command manually
  • Check ~/.rustycode/logs/ for connection errors
