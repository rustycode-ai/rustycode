Tips & Tricks

Get the most out of RustyCode. These patterns, commands, and strategies will help you develop faster, optimize token costs, and coordinate multi-agent teams.

Writing Effective Prompts

Providing clear and structured instructions prevents the agent from making unnecessary tool calls and wandering off course.

Use /do Command for Auto-Routing

Rather than manually specifying modes, type /do <your request> in the TUI. The model classifies the intent and automatically routes it to the best prompt template (e.g. code for changes, debug for investigation, ask for lookups).

Be Explicit About Files and Scope

Limit the agent's search space to minimize context pollution and speed up execution:

# Vague
"Look at why the email sending is failing."

# Recommended
"Look at the email handler in src/api/handlers.rs. Check only lines 80-140.
Ignore tests, configuration files, and other routes."

Provide Clear Constraints

"Refactor the authentication handler in src/routes/auth.rs:
- Do not introduce new dependencies.
- Ensure all errors use the anyhow crate.
- Write unit tests under tests/auth_tests.rs.
- Verify changes compile before finishing."

Optimizing API Costs (Model Tiering)

Using large reasoning models (like Claude Opus or o3) for every simple edit is expensive. RustyCode supports Junior/Senior Model Tiering to balance cost and quality:

  1. Set a Cheap Default: Configure your default provider/model to a faster, cost-efficient model (e.g. claude-haiku-4-5, gpt-4o-mini, or deepseek-coder-v2).
  2. Consult the Advisor: Use the /advisor <question> slash command in the TUI. This makes a one-shot query to your configured senior model (e.g. claude-sonnet-4-6 or claude-opus-4-7) for high-level guidance without cluttering your chat history.
  3. Apply Advice Locally: The junior model takes the senior advisor's guidance and handles the actual tool execution (editing files, running compilers).
💡
Budget Control:

You can enforce strict token limits and max turns in your local config.toml to prevent runaway loops from draining your API credits. See the Configuration Guide.

Multi-Agent Teams (Ensemble Mode)

For complex features, coordinate a team of specialized subagents working in parallel:

1. Preview the Team Structure

Type /teamwork-preview <task> in the TUI. The orchestrator analyzes the task complexity and details the team role mapping (e.g., Code Researcher, DB Debugger, Test Writer) before launching them.

2. Run in Ensemble Mode

# Run parallel teams using git worktree isolation
rustycode run --mode ensemble "Refactor the invoice calculation system"

This spawns multiple agents in parallel. Each agent works in an isolated Git worktree to avoid conflicts. Changes are merged only after passing validation and quality gates.

Project Context (CLAUDE.md)

Add a CLAUDE.md file in your project root. RustyCode reads this file automatically at startup to understand your codebase conventions:

# CLAUDE.md

## Build and Test Commands
- Build project: `cargo build`
- Run clippy: `cargo clippy --workspace --all-targets`
- Run tests: `cargo test --test auth_tests`

## Architecture
- `crates/core/` - Main database models and service layer
- `crates/api/` - Axum route handlers and middleware

## Code Style
- Use `anyhow::Result` for fallible functions.
- Never use `unwrap()` or `expect()` in production code.
- Prefer async/await over spawning thread blocks.
- Add comments explaining safety on any `unsafe` block.

Debugging Tips

Provide Compiler Error Logs

If a build fails, pass the exact compiler output to the agent:

"I got this build error:
error[E0382]: borrow of moved value: `user`
   --> src/auth/session.rs:42:15

Fix this borrow checker error."

Use LSP Tools for Symbol Lookups

Instruct the agent to use LSP tools to find definitions, implementations, and incoming/outgoing call hierarchies before changing signatures:

"Use lsp_incoming_calls to find where `process_billing` is called,
then list all its references before refactoring it."

Common Issues & Solutions

"Edit target not found" errors

This error occurs when the editor tool cannot find the exact line range to replace. To resolve this:

  • Instruct the agent to use read_file on the specific lines first to verify the code snippet before applying edits.
  • The editor automatically tries three matching strategies (exact match, line-ending-normalized match, and trimmed match). If it still fails, specify the file name and the target function name explicitly in your prompt.

Token limits / context budget warnings

If a session runs too long, the Context Budget Guard will trigger a warning. To free up context:

  • Type /clear to reset the chat history. Your file changes will remain intact.
  • Tell the agent to focus only on specific modules and ignore unrelated directories.
