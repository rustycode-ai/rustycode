Config File Locations

RustyCode uses a layered configuration system. Files are loaded in order, with later entries overriding earlier ones:

FilePurposePriority
~/.rustycode/config.tomlUser-level defaultsLow (base)
.rustycode/config.tomlProject-level overridesMedium
CLAUDE.mdProject instructions (auto-loaded)Context only
Environment variablesRuntime overridesHigh
CLI flagsOne-shot overridesHighest
Tip: Put API keys and personal preferences in ~/.rustycode/config.toml. Put project-specific settings (model choice, custom tools) in .rustycode/config.toml within the project root. Commit CLAUDE.md to git for team-shared instructions.

Full Config Reference

# ~/.rustycode/config.toml
# RustyCode Configuration

# ── Provider Settings ──────────────────────────────────────

[provider]
# Which provider to use by default
# Options: "anthropic", "openai", "ollama"
default = "anthropic"

# ── Anthropic Claude ───────────────────────────────────────

[provider.anthropic]
# Environment variable holding your API key
api_key_env = "ANTHROPIC_API_KEY"
# Model to use
model = "claude-sonnet-4-6"
# Maximum tokens in the response
max_tokens = 8192
# Temperature (0.0 = deterministic, 1.0 = creative)
temperature = 0.0
# Optional: custom base URL (for proxies)
# base_url = "https://api.anthropic.com"

# ── OpenAI ─────────────────────────────────────────────────

[provider.openai]
api_key_env = "OPENAI_API_KEY"
model = "gpt-4o"
max_tokens = 4096
temperature = 0.0
# Optional: use a compatible endpoint
# base_url = "https://api.openai.com/v1"
# Optional: organization ID
# organization = "org-..."

# ── Ollama (Local LLM) ────────────────────────────────────

[provider.ollama]
base_url = "http://localhost:11434"
model = "codellama"
# No API key needed for local models

# ── Orchestration ──────────────────────────────────────────

[orchestration]
# Max reasoning iterations before stopping
max_iterations = 3
# Max tool calls per autonomous task
max_tool_turns = 25
# Total wall-clock timeout in seconds
wall_clock_timeout_secs = 900
# Minimum tool calls before considering the task done
min_tool_calls_to_stop = 5

# ── Permissions ────────────────────────────────────────────

[permissions]
# Files that require explicit approval to read or edit
protected_paths = [
    ".env",
    "credentials.json",
    "id_rsa",
    "*.pem",
    "Cargo.toml",
    "package.json",
]
# Commands that run without asking for approval
auto_approve_commands = [
    "ls", "cat", "head", "tail", "wc",
    "find", "grep", "git status", "git log", "git diff",
    "cargo check", "cargo test", "cargo clippy",
]

# ── TUI Settings ───────────────────────────────────────────

[tui]
theme = "dark"
scrollback = 10000

Anthropic Claude Setup

1. Get an API Key

Visit console.anthropic.com, create an account, and generate an API key.

2. Set the Key

# Add to ~/.zshrc or ~/.bashrc
export ANTHROPIC_API_KEY="sk-ant-api03-your-key-here"

3. Choose Your Model

ModelBest ForSpeedCost
claude-haiku-4-5Quick fixes, simple editsFastestLowest
claude-sonnet-4-6 RecommendedFeature dev, refactoringFastMedium
claude-opus-4-7Architecture, deep analysisSlowerHighest

4. Configure

# Minimal (just use defaults)
# Only ANTHROPIC_API_KEY is needed

# Override model per-project in .rustycode/config.toml
[provider.anthropic]
model = "claude-opus-4-7"

5. Using a Proxy / Custom Endpoint

[provider.anthropic]
base_url = "https://your-proxy.example.com/v1"
api_key_env = "MY_PROXY_API_KEY"

OpenAI GPT Setup

1. Get an API Key

Visit platform.openai.com/api-keys and generate a key.

2. Set the Key

export OPENAI_API_KEY="sk-your-key-here"

3. Choose Your Model

ModelBest ForNotes
gpt-4oGeneral purpose codingBest OpenAI model for code
gpt-4o-miniQuick tasksCheaper, faster
gpt-4-turboLonger context128K context window

4. Configure

# Switch default provider to OpenAI
[provider]
default = "openai"

[provider.openai]
model = "gpt-4o"

5. OpenAI-Compatible Endpoints

Works with any OpenAI-compatible API (Azure OpenAI, Together AI, Groq, etc.):

[provider.openai]
base_url = "https://api.groq.com/openai/v1"
api_key_env = "GROQ_API_KEY"
model = "llama-3.1-70b-versatile"

Ollama (Local LLM) Setup

Run models locally with no API costs. Great for offline work or sensitive codebases.

1. Install Ollama

# macOS
brew install ollama

# Linux
curl -fsSL https://ollama.com/install.sh | sh

2. Start Ollama and Pull a Model

ollama serve
ollama pull codellama    # Code-focused model
ollama pull llama3       # General purpose
ollama pull deepseek-coder-v2  # Strong coding model

3. Configure RustyCode

[provider]
default = "ollama"

[provider.ollama]
base_url = "http://localhost:11434"
model = "codellama"
Note: Local models are less capable than Claude or GPT-4 for complex tasks. They work best for small, well-scoped edits and quick lookups.

Custom Endpoints

Any provider with an OpenAI-compatible API works by setting base_url:

Azure OpenAI

[provider.openai]
base_url = "https://your-resource.openai.azure.com/openai/deployments/your-deployment"
api_key_env = "AZURE_OPENAI_API_KEY"
model = "gpt-4o"

Together AI

[provider.openai]
base_url = "https://api.together.xyz/v1"
api_key_env = "TOGETHER_API_KEY"
model = "meta-llama/Meta-Llama-3.1-70B-Instruct-Turbo"

Groq (Fast Inference)

[provider.openai]
base_url = "https://api.groq.com/openai/v1"
api_key_env = "GROQ_API_KEY"
model = "llama-3.1-70b-versatile"

Tool Permissions

How Permissions Work

Every tool action goes through the permission system:

  1. Auto-approve — Read-only commands like ls, git status, cargo check
  2. Ask user — File writes, shell commands, anything that modifies state
  3. Block — Sensitive files (.env, SSH keys), dangerous commands (rm -rf)

Customizing Auto-Approve

[permissions]
auto_approve_commands = [
    # Existing defaults
    "ls", "cat", "head", "tail", "wc", "find", "grep",
    "git status", "git log", "git diff", "git branch",
    "cargo check", "cargo test", "cargo clippy",
    # Add your own
    "docker ps",
    "kubectl get pods",
    "make lint",
]

Orchestration Tuning

Fine-tune autonomous mode behavior:

SettingDefaultWhat It Does
max_iterations3How many times the agent can reconsider its approach. Increase for complex tasks.
max_tool_turns25Maximum tool calls per task. Prevents runaway execution.
wall_clock_timeout_secs900Hard timeout in seconds. The agent stops no matter what after this.
min_tool_calls_to_stop5Prevents the agent from stopping too early. Must make at least this many tool calls.
For large refactors: Increase max_tool_turns to 40 and wall_clock_timeout_secs to 1800. For quick fixes: Decrease max_iterations to 1 and min_tool_calls_to_stop to 2.
