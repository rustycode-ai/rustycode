Configuration Reference

RustyCode is configured using TOML files and environment variables. This reference explains how to structure your configurations globally and locally.

Config Locations

RustyCode reads configuration files sequentially, applying project-level overrides on top of user-level defaults. Each directory accepts config.toml, config.json, or config.jsonc (JSON with comments; later files win within the same directory):

PriorityPathDescription
1 (Base) ~/.rustycode/config.{toml,json,jsonc} Global configurations. Put API keys and personal defaults here.
2 ~/.config/rustycode/config.{toml,json,jsonc} XDG global configuration. Overrides the legacy home directory.
3 .rustycode-workspace/ (walking up parents) Shared workspace layer for multi-repo projects, anchored by the marker directory.
4 .rustycode/config.{toml,json,jsonc} in the project Project-level overrides. Put project models and custom tools here.
5 CLAUDE.md Workspace instructions. Read automatically to guide code style and paths.
6 (Highest) Environment Variables Keys prefixed with RUSTYCODE_ override config file settings at runtime.

Full TOML Sample

Here is a complete config.toml showcasing the available tables. The active provider and model are top-level keys; per-provider settings live under [providers.<name>]:

# ~/.rustycode/config.toml

# ── Core Settings ──────────────────────────────────────────
provider = "anthropic"          # active provider name
model = "claude-sonnet-4-6"     # active model
# temperature = 0.0
# max_tokens = 8192
# timeout_seconds = 120

# ── Anthropic Claude ───────────────────────────────────────
[providers.anthropic]
# api_key = "sk-ant-..."       # or export ANTHROPIC_API_KEY
# base_url = "https://api.anthropic.com"
# models = ["claude-sonnet-4-6", "claude-opus-5", "claude-haiku-4-5"]

# ── OpenAI ─────────────────────────────────────────────────
[providers.openai]
# api_key = "sk-..."           # or export OPENAI_API_KEY
# models = ["gpt-4o"]

# ── Google Gemini ──────────────────────────────────────────
[providers.gemini]
# api_key = "..."              # or export GOOGLE_API_KEY

# ── Ollama (Local) ─────────────────────────────────────────
[providers.ollama]
base_url = "http://localhost:11434"

# ── MCP Servers ────────────────────────────────────────────
# A keyed map under `advanced.mcp_servers_map`. Transport is
# auto-detected: `command` → stdio, `url` → http.
[advanced.mcp_servers_map.postgres]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-postgres", "postgresql://localhost/mydb"]
# env = { PGUSER = "postgres" }

[advanced.mcp_servers_map.remote-api]
url = "https://mcp.example.com/mcp"

# ── Directories ────────────────────────────────────────────
# data_dir = "~/.rustycode/data"
# memory_dir = "~/.rustycode/memory"
# skills_dir = "~/.rustycode/skills"
# lsp_servers = ["rust-analyzer"]

# Other registered provider names: vertex, azure, bedrock,
# openrouter, zhipu, mistral, cohere, together, perplexity,
# nvidia, huggingface, kimi-*, alibaba-*, lmstudio, copilot,
# litert-lm, opencode — select with the top-level `provider` key.

# Execution budgets are not TOML keys — they come from loop-tier
# defaults and the environment variables listed under
# "Orchestration & Budgets" below.

LLM Providers

Anthropic

Recommended for its coding capability. Set ANTHROPIC_API_KEY. Recommended models:

  • claude-sonnet-4-6: Balanced model for feature development and editing.
  • claude-opus-5: High-effort model for architecture and diagnostics.
  • claude-haiku-4-5: Fast and cost-efficient option for simple, single-file patches.

Google Cloud Vertex AI

Utilize corporate Gemini models hosted via Google Cloud Vertex. Ensure the local environment has active credentials via gcloud auth application-default login, then activate the provider with the top-level keys:

provider = "vertex"
model = "gemini-2.5-pro"

Ollama

Point [providers.ollama] base_url to your local port (default http://localhost:11434), set the top-level provider = "ollama", and pick a downloaded model with the top-level model key (e.g. qwen2.5-coder or deepseek-coder-v2).

MCP Configurations

Define third-party MCP servers as a keyed map under [advanced.mcp_servers_map.<name>]. The transport is auto-detected from the fields you provide (command → stdio, url → http/sse); environment variables go in an env table:

[advanced.mcp_servers_map.github]
command = "npx"
args = ["-y", "@modelcontextprotocol/server-github"]
env = { GITHUB_PERSONAL_ACCESS_TOKEN = "ghp_..." }

Permissions & Paths

File and command safety is built in rather than user-configured:

  • Blocked files: A built-in validation layer refuses tool reads/writes to sensitive files by default — .env* variants, *.pem/*.key/*.p12, credentials.json, id_rsa, .netrc, .npmrc, wallet/database files, and binary executables. Secrets are also stripped from logs via sanitize_for_log().
  • Command approval: Read-only commands are auto-approved by a classifier; anything else (edits, shell side effects) prompts an explicit TUI/Web approval dialog before execution.
  • Escape hatch: --dangerously-skip-permissions or RUSTYCODE_SKIP_PERMISSIONS=true disables the checks — only for sandboxed containers and CI.

Orchestration & Budgets

Prevent runaway loops and coordinate agent workloads. Budgets are set by loop tier and overridden with environment variables (not TOML keys):

OverrideDefaultDescription
RUSTYCODE_MAX_TURNS 25 (Tier 3) Maximum LLM↔tool turns per run. Tier defaults scale with task complexity: 5 (Tier 1), 10 (Tier 2), 25 (Tier 3+). Also settable per-run with rustycode run --max-turns <n>.
RUSTYCODE_AGENT_TIMEOUT_SECS 900 (Tier 3) Hard wall-clock timeout. Forces the agent to shut down and output results. Tier defaults: 60s (Tier 1), 120s (Tier 2), 900s (Tier 3+).
RUSTYCODE_MAX_OUTPUT_TOKENS 32768 Caps the model's output token budget per response.
RUSTYCODE_EFFORT_OVERRIDE model default Reasoning effort (low|medium|high|xhigh|max) on supported models.

Environment Variables

Override TOML files at runtime using environment variables:

VariableTOML OverrideExample
RUSTYCODE_PROVIDER provider.default export RUSTYCODE_PROVIDER="google"
RUSTYCODE_MODEL_OVERRIDE Active model name export RUSTYCODE_MODEL_OVERRIDE="gpt-4o"
RUSTYCODE_EFFORT_OVERRIDE Reasoning effort limit export RUSTYCODE_EFFORT_OVERRIDE="medium"
RUSTYCODE_MAX_TURNS Max LLM↔tool turns export RUSTYCODE_MAX_TURNS="25"
RUSTYCODE_AGENT_TIMEOUT_SECS Wall-clock timeout export RUSTYCODE_AGENT_TIMEOUT_SECS="900"
RUSTYCODE_SKIP_PERMISSIONS Skips security checks export RUSTYCODE_SKIP_PERMISSIONS="true"
