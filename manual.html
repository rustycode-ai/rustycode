User Manual

This reference manual details the CLI command structure, TUI controls, Web interface, native tools, reasoning pipelines, and sandboxing architecture in RustyCode.

CLI Subcommands

The rustycode CLI is structured into specialized subcommands to manage sessions, workflows, providers, and local indexes.

SubcommandUsageDescription
tui rustycode tui [--resume] [--model <m>] Launch the interactive, fullscreen Terminal UI.
run rustycode run "<prompt>" [--mode <m>] Execute a task directly in headless mode and output the results.
serve rustycode serve [--port <p>] Boot the backend API server carrying the Web UI, ACP endpoint, and A2A system.
doctor rustycode doctor Validate binary pathing, configs, local database logs, and check connectivity of providers.
repair rustycode repair <session-id> --test-file <t> Diagnose and auto-repair a failing agent run from its JSONL trace rollout.
checkpoint rustycode checkpoint <git-hash> [-f <files>] Roll back codebase workspace to a Git hash checkpoint, optionally restoring specific files.
workflow rustycode workflow <cmd> --description <task> Execute static DAG or dynamic Rhai-scripted multi-agent pipelines.
plan rustycode plan create "<goal>" Create, list, show, approve, or reject structured execution plans.
chat rustycode chat setup telegram Configure remote control from chat platforms (see the Chat Control guide).
login / auth-status rustycode login anthropic Authenticate with a provider (OAuth, device flow, or API key) and show auth status.
mcp rustycode mcp <command> Run the MCP server exposing RustyCode tools over stdio.
agent rustycode agent new "<task>" Start a single, standalone background reasoning session.
omo rustycode omo <command> Run multi-agent code analysis loops to survey architecture boundaries.
harness rustycode harness run Launch the persistent harness runner for SWE-bench evaluations.
worktree rustycode worktree <command> Manage isolated Git worktrees for parallel agent executions.
skills rustycode skills install <git/url> Manage YAML skills. Installs to .agents/skills/ by default.
learnings rustycode learnings show Show, register, or clear memories learned across previous coding tasks.
wiki rustycode wiki search "<query>" Interact with project wikis (ingest logs, hybrid search, or query entries).
provider rustycode provider list Display configured LLM model registries and current capabilities.
history rustycode history list Manage past session histories (list, search, show, or export JSONL rolls).
acp rustycode acp <command> Manage the IDE integration server (Agent Client Protocol).
a2a rustycode a2a <command> Manage agent-to-agent communication links.
memory rustycode memory stats Print stats or prune keys within the vector memory database.
update rustycode update [--nightly] Self-update the local binary to the latest release or nightly build.
tools rustycode tools list List all registered tools, or invoke one directly with tools call <name> --params '{...}'.
sessions rustycode sessions list Manage past sessions: list, show, archive, restore, or purge old ones.
events rustycode events watch Watch the internal event bus stream in real time with pattern filtering.
context rustycode context "<prompt>" Plan the context budget for a prompt: which layers fit and their token share.
ast rustycode ast run "<task>" Run a task through the AST pipeline (CLASSIFY → RESEARCH → SKELETON → EXPAND → EXECUTE → VERIFY).
outline rustycode outline <file> Explore code structure of a file (experimental).

Global Flags

Apply these flags to any subcommand to override execution-wide defaults:

FlagDescription
--yesBypasses all interactive confirmation gates (forced non-interactive mode).
--model <name>Override provider defaults for the primary LLM (e.g. --model claude-opus-5).
--effort low|medium|high|xhigh|maxSpecify reasoning token budgets or effort modes on supported models.
--format human|jsonStdout structure format (default: human). Use json for machine pipes.
--color always|never|autoConfigure ANSI color rendering in stdout logs.
--dangerously-skip-permissionsDisable security permission checks. Recommended only for isolated Docker/CI.
--verbose / --debugPrint detailed debug and tracing logs to the console.

Terminal UI & Slash Commands

The Ratatui-based TUI supports rich rendering, tab-switching, and inline commands. Type a slash command in the message input bar to coordinate sessions:

Slash Commands

CommandPurpose
/do <prompt>Perform natural language mode routing (auto-select code, debug, or ask context).
/advisor <query>Consult the senior model advisor about an issue without committing it to the main context history.
/workflow <goal>Boot the dynamic workflow runner to generate and coordinate parallel task steps.
/goal <task>Run a thorough autonomous session that persists until the goal is validated.
/team <task>Run a multi-agent team (researcher, implementer, reviewer) in parallel with git worktree isolation.
/compact / /ccSummarize and compact the conversation to free context without losing key decisions.
/undo / /uRevert the agent's most recent file change.
/clearReset the current conversation, clear file caches, and release workspace guards.
/load <path>Load a specific file or past conversation transcript into the active context.

Web Interface

Start the web server with rustycode serve or rustycode web start. Key dashboard widgets:

  • Chat View: Real-time streaming markdown renderer caching.
  • Interactive Diff Pane: View code changes in side-by-side view with line-by-line acceptance.
  • Vision Canvas: Drag and drop images/mockups. Handled securely with size limits and fed to vision-enabled LLMs.
  • Command Palette: Hit Ctrl+K to change models, select skills, or search conversation history.

Built-in Tools

RustyCode equips agents with built-in tools. Each tool execution undergoes strict permission checks:

  • File Reading: read_file (with chunk offsets/limits for huge assets).
  • File Writing: write_file and edit_file (incorporates exact, normalized, and trimmed match heuristics).
  • Notebook Editing: notebook_edit to read/insert/delete Jupyter Notebook cells.
  • Code Search: grep (regex, line context, file filters) and glob (path pattern expansion).
  • Shell Execution: bash (background tasking, environment sandboxing, timeout limits).
  • LSP Nav: lsp_references, lsp_document_symbols, lsp_implementation, lsp_incoming_calls, lsp_outgoing_calls.
  • Web Fetch: web_fetch to pull URLs, automatically converting HTML pages into clean Markdown.

Reasoning & Model Tiering

To optimize execution speed and API expenses, RustyCode uses Senior/Junior Model Tiering:

            ┌──────────────────────────────────────────┐
            │        Junior Model (e.g. Haiku)         │
            │  Standard reasoning & tool execution loop │
            └────────────────────┬─────────────────────┘
                                 │
                     [Stuck / Complex Check]
                                 │
                                 ▼
            ┌──────────────────────────────────────────┐
            │       Senior Model (e.g. Sonnet/Opus)    │
            │       Triggered via /advisor or gate     │
            └──────────────────────────────────────────┘

Standard editing loops run on lower-tier models. If the agent gets stuck (repeated tool failures or confidence dips), it makes a targeted query to a senior "advisor" model to break the deadlock, returning the instructions back to the junior execution thread.

Intelligence Guards

Four key guards validate agent trajectories in real time to prevent runaway loops and token drain:

  • Streaming Repetition Guard: Inspects streaming tokens for repeating loops and terminates early if detected.
  • Repeated Failure Guard: Halts execution if a tool (like a test bash script) fails repeatedly with the same signature.
  • Context Budget Guard: Monitors conversation length and triggers context compaction or pruning before hitting model limits.
  • Completion Gate: An independent evaluator checks the output criteria against the original goal before concluding a session.

Security & Sandboxing

To run untrusted scripts safely, RustyCode enforces OS-level sandboxing:

Operating SystemSandbox DriverRestrictions
macOS Seatbelt Enforces strict sandbox-exec profiles blocking custom network pipes and restricting write paths.
Linux Landlock Kernel-level filesystem access restriction (requires Linux kernel 5.13+).
Windows / Containers Podman/Docker fallback Routes commands to isolated containers with path-traversal sanitizers.
