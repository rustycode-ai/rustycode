Chat Remote Control Setup Guide

RustyCode can be remote-controlled from six chat platforms: **Telegram, WhatsApp, Slack, LINE, Google Chat, and Discord**. Send messages from your chat app to drive a live session—complete with tool approvals, interactive diffs, and console commands.

Overview

The chat surface acts as a thin remote-control client over WebSockets—it is not a separate autonomous agent. Inbound messages are routed directly into the active session as user inputs; outbound events (assistant text, terminal outputs, tool requests) are rendered back into your chat client.

Fast Path Setup

Set up your chat provider in a few commands using the built-in wizard:

# See all available chat transport providers
rustycode chat list

# Run the interactive configuration wizard (writes ~/.rustycode/config.toml)
rustycode chat setup telegram

# Print the TOML snippet and instructions without opening a browser
rustycode chat setup slack --print

# Run non-interactively (useful if env vars already provide credentials)
rustycode chat setup slack --yes

Remote Round-Trip

Once you pair a chat client, session steering operates in three directions:

  • RECEIVE: Messages you send to the bot are ingested as user prompts in the session.
  • SEND: Session events (Assistant text streams, file diffs, tool requests) are delivered to your chat.
  • CONTROL: Interactive buttons allow you to steer the session. If buttons are not supported by the platform, use text commands: /approve <request_id> or /reject <request_id>.

Connection Models

Depending on the platform, RustyCode establishes connections in one of three ways:

ModelSupported ProvidersRequirementsDescription
Long-Poll Telegram Bot token only The local agent polls the platform API. No public URL/tunnel needed.
Socket/Gateway Slack, Discord App/Bot tokens Establishes a persistent outbound WebSocket. No public URL/tunnel needed.
Webhook LINE, Google Chat, WhatsApp Cloud API Credentials + Public URL Requires exposing the local webhook port to the internet via tunnels (e.g., Cloudflared or Ngrok).

Allow-List Security

Transports fail closed: an empty allow-list blocks all incoming messages. You must explicitly configure allowed user IDs in the [chat] section of ~/.rustycode/config.toml:

[chat]
enabled = true          # Must be set to true
topology = "shared"
allow = ["tg:123456789", "slack:U0123ABC", "discord:987654321"]

# Optional: override models and directories for chat-specific runs
[chat.session]
model = "claude-sonnet-4-6"
working_directory = "."

Telegram Bot Setup

  1. Open @BotFather in Telegram and type /newbot. Copy the **Bot Token**.
  2. Get your numeric user ID by messaging @userinfobot.
  3. Write the settings to your ~/.rustycode/config.toml:
[chat]
enabled = true
allow = ["tg:<your-numeric-id>"]

[chat.telegram]
enabled = true
bot_token = "123456789:ABCdef..."

Start the remote control in the TUI using: :remote telegram (renders a pairing QR code).

Slack App Setup (Socket Mode)

  1. Create a Slack application on the Slack Console.
  2. In OAuth & Permissions, add scopes: chat:write, im:history, channels:history, and app_mentions:read.
  3. Install the app to your workspace and copy the **Bot User OAuth Token** (starts with xoxb-).
  4. In Basic Information, copy the **Signing Secret** and enable **Socket Mode** (copies an App Token starting with xapp-). Under Event Subscriptions, subscribe to events: message.channels, message.im, and message.groups.
  5. Configure `~/.rustycode/config.toml`:
[chat]
allow = ["slack:<your-user-or-team-id>"]

[chat.slack]
enabled = true
app_token = "xapp-..."          # Socket Mode token
bot_token = "xoxb-..."          # Bot OAuth token
signing_secret = "..."          # Signing secret

Start the connection in the TUI using: :remote slack.

WhatsApp Setup

WhatsApp supports two modes: **paired-device Web** session (uses a local headless browser session, no webhook needed) or **Cloud API** (webhook-fed for bidirectional flow).

[chat]
allow = ["wa:<your-phone-number>"]

[chat.whatsapp]
enabled = true
mode = "web"                     # "web" for paired-device or "cloud" for Cloud API
access_token = "..."             # Cloud API Token
phone_number_id = "..."          # Cloud API Phone ID
webhook_url = "https://yourtunnel.com/webhook/whatsapp"

Discord Bot Setup

  1. Create an application on the Discord Developer Portal. Add a Bot, copy the **Bot Token**, and enable **Message Content Intent** under the Bot menu.
  2. Write settings to your TOML config:
[chat]
allow = ["discord:<your-discord-user-id>"]

[chat.discord]
enabled = true
bot_token = "<your-bot-token>"

Run :remote discord in the TUI to establish a persistent Gateway WebSocket connection.

LINE & Google Chat Setup

LINE Messenger

Requires Channel Access Token and Channel Secret. Inbound messages are processed via webhooks:

[chat.line]
enabled = true
channel_access_token = "..."
channel_secret = "..."

Expose your webhook and register https://<public-base>/webhook/line in the LINE console.

Google Chat

Google Chat uses Spaces incoming webhooks for outbound messages, and webhook endpoints for inbound HTTP apps:

[chat.google_chat]
enabled = true
webhook_url = "https://chat.googleapis.com/v1/spaces/..."
webhook_secret = "..."           # Shared key for HMAC verification

Troubleshooting & Security

  • Slack `missing_scope` Errors: Ensure you are using the app's **Bot User OAuth Token** (starts with xoxb-) and not the User Token. Check that chat:write is granted.
  • Allow-List Rejection: Verify your user IDs are correctly prefixed (e.g. tg:, slack:, discord:). Unlisted IDs are rejected by default.
  • Google Chat/Discord Webhooks: Bare incoming webhooks are outbound-only by platform design. For bidirectional flow (RECEIVE/CONTROL), you must set up a full Discord application (Gateway mode) or a Google Chat HTTP app endpoint.
  • HMAC Signature Verification: To secure public webhook endpoints, configure `webhook_secret` in `[chat.discord]` or `[chat.google_chat]` to enforce signature verification on inbound requests.
