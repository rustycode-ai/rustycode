Skills, MCP & Tools

RustyCode's modular tool ecosystem allows the agent to navigate directories, run browser tasks, control the host desktop, and interface with IDEs.

Overview

Capabilities are structured across several interfaces:

Skills System

Markdown files carrying YAML triggers that teach the agent specific coding patterns and quality checklists.

MCP client

Runs external server binaries via stdio or HTTP/SSE, bridging their tools directly into the LLM context.

Built-in MCP

Four embedded servers for desktop control, headless browser tasks, container commands, and search queries.

ACP Server

Agent Client Protocol listener mapping JSON-RPC loops to IDE editors like VS Code and JetBrains.

A2A Protocol

Agent-to-Agent protocol enabling peer agents to hand off subtasks, query capacities, and merge results.

Custom Tools

Rust-native tools written by implementing the ToolExecutor trait in the workspace registry.

Skills System

Skills represent procedural recipes. The agent automatically discovers skills when matching prompt tags and matches them against directories:

  • Workspace local: .agents/skills/ (standard path) or .rustycode/skills/ (legacy path).
  • User global: ~/.rustycode/skills/.

Installing Skills

Install skills from a local file, git repository, or HTTPS endpoint directly into your workspace:

# Install into default workspace directory (.agents/skills/)
rustycode skills install https://github.com/luengnat/rustycode-skills/raw/main/rust-refactor.md

# Install into legacy directory (.rustycode/skills/)
rustycode skills install https://example.com/skills/postgres-migration.md --legacy

Skill File Sample

Skills use YAML headers to specify keywords (triggers) that prompt the agent to load them:

---
name: rust-refactor-helper
description: Guidelines for refactoring Rust crates safely with LSP tools
triggers:
  - refactor
  - rename symbol
  - extract function
tags:
  - rust
  - refactor
---

# Rust Refactoring Checklist

## Preparation
1. Ensure the workspace is clean (`git status`).
2. Run `cargo check` before starting to verify no pre-existing compiler errors.

## Refactor Loop
1. Run `lsp_references` to count code references before modifying a struct or function signature.
2. Edit target code using `edit_file`.
3. Check the compiler: `cargo clippy --workspace --all-targets`.
4. Run integration tests: `cargo test`.

## Verify
- [ ] No compilation warnings or errors.
- [ ] Clippy warnings have been cleared.
- [ ] Unit tests pass successfully.

Built-in MCP Servers

RustyCode embeds four Model Context Protocol backends to extend the agent's capabilities:

Crate/ServerToolsDescription
rustycode-mcp-browser 7 Automate Chromium processes: navigate, screenshot page, click coordinates, enter text, evaluate JavaScript, and retrieve raw HTML/text.
rustycode-mcp-docker 7 Manage docker images and containers: build, run, stop, inspect, and extract container logs. Features Podman fallback and path traversal safety.
rustycode-mcp-web 2 Fetch URLs (automatically converting HTML to clean Markdown) and run search queries using Wikipedia, DuckDuckGo, or Exa APIs.
rustycode-mcp-computer-use 15 Inject keyboard and mouse inputs, capture screenshots, and query window positions with platform-aware surface routing.

Computer Use & Surface Routing

The rustycode-mcp-computer-use server gives agents visual and interactive control over the host desktop. It uses Surface-Aware Routing to help the agent decide how to interact with different windows:

  1. Terminal: If the active window is classified as a terminal (e.g. iTerm2, cmd.exe, xterm), the agent routes commands to the native bash tool instead of clicking coordinates.
  2. Web Browser: If the window is a browser (e.g. Safari, Chrome), the agent chooses headless browser CDP tools for faster, coordinate-free scraping.
  3. GUI Application: For standard GUI applications, the agent falls back to mouse coordinate clicking, typing, and drag actions.
⚠
Platform Permissions Required:

macOS: Open System Settings > Privacy & Security. Grant "Screen Recording" and "Accessibility" permissions to the terminal or app hosting RustyCode.
Linux: Requires an active X11 desktop session and the libxdo0 package installed.
Windows: Runs in any interactive user session.

ACP (IDE Integration)

The Agent Client Protocol (ACP) server bridges RustyCode directly into IDE editors (like VS Code or JetBrains) over JSON-RPC. This allows you to interact with the agent within your editor. Start the background daemon:

# Serve the web client and ACP handler concurrently
rustycode serve --port 3000

# Or start the ACP service separately
rustycode acp start

A2A (Multi-Agent Protocol)

The Agent-to-Agent (A2A) protocol enables multi-agent teamwork over HTTP and JSON-RPC. In A2A environments, agents advertise their capabilities using a standardized JSON schema at /.well-known/agent-card.json. This allows:

  • Handoffs: A general coding agent can spawn a specialized database subagent.
  • Parallel Teams: Dividing large features into separate worktree modules managed by distinct agents.
  • Scoring: Verifying code modifications using blind judges scoring.

Creating Custom Tools

Create native tools by implementing the ToolExecutor trait from the rustycode-tools-api crate. Register your struct with the tool registry:

// crates/rustycode-tools/src/providers/my_custom_tool.rs
use anyhow::Result;
use rustycode_tools_api::{ToolExecutor, ToolResult, ToolContext};
use serde_json::{json, Value};

pub struct PortScannerTool;

impl ToolExecutor for PortScannerTool {
    fn name(&self) -> &str {
        "scan_ports"
    }

    fn description(&self) -> &str {
        "Check if specific ports are open on the local host"
    }

    fn parameters(&self) -> Value {
        json!({
            "type": "object",
            "properties": {
                "host": { "type": "string", "description": "Host domain or IP" },
                "ports": { "type": "array", "items": { "type": "integer" } }
            },
            "required": ["host", "ports"]
        })
    }

    async fn execute(&self, ctx: &ToolContext) -> Result<ToolResult> {
        let host = ctx.param_str("host")?;
        let ports: Vec<u16> = ctx.param_as("ports")?;
        
        let mut results = Vec::new();
        for port in ports {
            let address = format!("{}:{}", host, port);
            let is_open = tokio::net::TcpStream::connect(&address).await.is_ok();
            results.push(format!("Port {}: {}", port, if is_open { "OPEN" } else { "CLOSED" }));
        }

        Ok(ToolResult::text(results.join("\n")))
    }
}

Register the custom tool

Add the tool to the registry initialization in crates/rustycode-tools/src/lib.rs:

let mut registry = ToolRegistry::new();
registry.register(Box::new(PortScannerTool));
