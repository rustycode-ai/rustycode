Overview

RustyCode's extensibility comes from three layers:

Skills

Markdown instruction files that guide the LLM's behavior for specific tasks. Think of them as "recipes" the agent follows.

MCP Servers

External tools and data sources connected via the Model Context Protocol. Add databases, APIs, and services.

Built-in Tools

File editing, shell execution, search, LSP — always available, no setup needed.

Skills

Skills are Markdown files with YAML frontmatter that teach RustyCode how to handle specific tasks. They live in .rustycode/skills/ or ~/.rustycode/skills/.

What Skills Do

  • Provide step-by-step instructions for complex workflows
  • Define checklists and quality gates
  • Encapsulate domain knowledge (e.g., Rust patterns, testing strategies)
  • Enforce team conventions automatically

How Skills Are Loaded

RustyCode automatically discovers skills when a session starts:

  1. User skills from ~/.rustycode/skills/ — personal, apply everywhere
  2. Project skills from .rustycode/skills/ — team-shared, project-specific

Skills are matched by keywords in your prompt. If you say "debug the auth timeout", RustyCode loads the debugging skill and any auth-related project skills.

Installing Skills

From a Repository

# Clone skill files into your project
mkdir -p .rustycode/skills
curl -sL https://example.com/skills/rust-patterns.md \
  -o .rustycode/skills/rust-patterns.md

Global (Personal) Skills

# Skills available in all projects
mkdir -p ~/.rustycode/skills
cp my-custom-skill.md ~/.rustycode/skills/

Directory Structure

project/
├── .rustycode/
│   ├── config.toml
│   └── skills/
│       ├── code-review.md
│       ├── testing.md
│       └── deployment.md

Creating Custom Skills

Skills use YAML frontmatter for metadata and Markdown for instructions:

---
name: database-migration
description: Guide for creating safe database migrations
triggers:
  - migration
  - database
  - schema change
tags:
  - database
  - postgresql
  - migration
---

# Database Migration Skill

## Pre-Flight Checks
1. Read the current schema from `migrations/schema.sql`
2. Check if the migration has a corresponding down-migration
3. Verify no other migration is in progress (check git branch)

## Steps
1. Create a new file `migrations/YYYYMMDD_description.sql`
2. Write the up-migration with explicit column types
3. Write the down-migration in the same file (commented)
4. Test: `cargo test --test migration_test`

## Checklist
- [ ] Migration is reversible (has a down-migration)
- [ ] No data loss for existing rows (add columns as nullable first)
- [ ] Indexes are created concurrently for large tables
- [ ] Migration file name follows the date_description convention

Model Context Protocol (MCP)

MCP is an open protocol that lets RustyCode connect to external tools and data sources. MCP servers provide:

  • Tools — Actions the LLM can take (query a database, call an API)
  • Resources — Data the LLM can read (files, database schemas)
  • Prompts — Pre-built prompt templates

How MCP Works

┌─────────────┐     stdio/SSE     ┌──────────────┐
│  RustyCode   │ ◄───────────────► │  MCP Server   │
│  (Client)    │                   │  (e.g., Postgres)
└─────────────┘                   └──────────────┘

RustyCode starts MCP servers as subprocesses and communicates via JSON-RPC over stdio (or HTTP/SSE for remote servers).

Installing MCP Servers

Configure MCP servers in your config file:

PostgreSQL Server

# In ~/.rustycode/config.toml or .rustycode/config.toml

[[mcp_server]]
name = "postgres"
transport = "stdio"
command = "npx"
args = ["-y", "@modelcontextprotocol/server-postgres", "postgresql://localhost/mydb"]

Filesystem Server

[[mcp_server]]
name = "filesystem"
transport = "stdio"
command = "npx"
args = ["-y", "@modelcontextprotocol/server-filesystem", "/home/user/projects"]

GitHub Server

[[mcp_server]]
name = "github"
transport = "stdio"
command = "npx"
args = ["-y", "@modelcontextprotocol/server-github"]
env = { GITHUB_PERSONAL_ACCESS_TOKEN = "ghp_..." }

Remote Server (SSE)

[[mcp_server]]
name = "custom-api"
transport = "sse"
url = "https://mcp.example.com/v1/sse"
headers = { Authorization = "Bearer your-token" }

Prerequisites for MCP Servers

Most MCP servers are Node.js packages. You need:

# Install Node.js (if not already installed)
brew install node        # macOS
# or use nvm, fnm, etc.

# MCP servers are auto-installed via npx on first use
# No separate install step needed
Tip: Use npx -y in the command to auto-install the MCP package on first run. This avoids a separate install step.

Creating Custom Tools

You can extend RustyCode with custom tools by implementing the ToolExecutor trait from rustycode-tools-api:

1. Create a Tool Module

// src/my_tool.rs
use rustycode_tools_api::{ToolExecutor, ToolResult, ToolContext};

pub struct MyTool;

impl ToolExecutor for MyTool {
    fn name(&self) -> &str {
        "my_tool"
    }

    fn description(&self) -> &str {
        "Does something custom with the codebase"
    }

    fn parameters(&self) -> serde_json::Value {
        serde_json::json!({
            "type": "object",
            "properties": {
                "input": {
                    "type": "string",
                    "description": "What to process"
                }
            },
            "required": ["input"]
        })
    }

    async fn execute(&self, ctx: &ToolContext) -> Result<ToolResult> {
        let input = ctx.param("input")?;
        // Your logic here
        Ok(ToolResult::text(format!("Processed: {}", input)))
    }
}

2. Register the Tool

// In your tool registry or main.rs
use rustycode_tools::executor::ToolRegistry;

let mut registry = ToolRegistry::new();
registry.register(Box::new(MyTool));

3. Add Security Validation (if needed)

// If your tool touches files or runs commands, add validation
use rustycode_tools::security::validate_path;

let path = validate_path(&requested_path)?;
